01 / CONTEXT

The brief

Citizen Success brought a political geography database and a subscription publishing product into the same application. The data model covered parties, politicians, states, legislative chambers, and divisions. The product also needed content creation, access permissions, payments, and interactive conversations.

02 / RESPONSIBILITY

What I owned

  • Build the application and the public-data search experience.
  • Connect publishing, subscriptions, permissions, and payment integrations.
  • Operate the deployment, database, storage, email, and backup environment.

03 / EXECUTION

How the work was delivered

Phoenix LiveView powered reactive filtering and real-time post chat. Channels, posts, custom page layouts, a rich-text editor, and S3 uploads supported the publishing workflow. React and Svelte components were integrated into LiveView where needed, while a theming engine supported multiple sites and domains.

The implementation connected Stripe through JSON/REST and Authorize.Net through XML. A permission system expressed access in terms of users, powers, actions, and schemas. The self-hosted environment used Debian, Ansible, PostgreSQL, and Docker Compose, with Wasabi S3 storage, Cloudflare CDN, and geographically redundant backup arrangements.

04 / EVIDENCE

Delivery and evidence

  • Delivered a searchable political database and publishing application in one product.
  • Provided political database queries and lists to campaigns.
  • Built the operational foundation for multiple sites, subscriptions, and real-time content interactions.

THE OPERATING LESSON

Founder-led product engineering includes the less visible work: permissions, backups, publishing operations, and maintainable integrations. Those capabilities make the visible product usable in practice.
